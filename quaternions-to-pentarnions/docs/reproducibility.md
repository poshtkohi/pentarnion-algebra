# Reproducibility workflow

Keep the reference `part-I/data/` and `part-II/data/` trees read-only. They contain
the supplied paper records. Use the separate generated tree printed by each
runner; CSV ZIPs are read without manual extraction.

## Checks and figures

```bash
python quaternions-to-pentarnions/run_checks.py --level quick
python quaternions-to-pentarnions/run_checks.py --part I --level exact
python quaternions-to-pentarnions/run_checks.py --part II --level exact
python quaternions-to-pentarnions/run_checks.py --level full --plots
```

The full checks include the ordered-product coefficient solve and six generic
Jacobian determinants. Plotting produces all 54 listed image inputs. It is a
separate operation from numerical integration. [Figure inventory](figure_map.md).

## Numerical workflows

A C++17 `g++`/`clang++` compiler is required. Select it with `--compiler` if needed.
`--build-profile recorded` is the default: it uses the original documented
`-march=native` flags for the static/frequency scans, peaks scan and full-spectrum
driver, with portable flags for the other sources. `--build-profile portable`
omits native flags throughout; `native` applies them throughout. Each exact
command is recorded. Native results still depend on the CPU/compiler. GCC builds enable OpenMP; Clang can
run serially. Set `--threads` to control OpenMP threads.

```bash
python quaternions-to-pentarnions/run_numerics.py --task smoke
python quaternions-to-pentarnions/run_numerics.py --task scans
python quaternions-to-pentarnions/run_numerics.py --task branches
python quaternions-to-pentarnions/run_numerics.py --task validation
python quaternions-to-pentarnions/run_numerics.py --task spin-scan
python quaternions-to-pentarnions/run_numerics.py --task all --plots
```

The `smoke` task is deliberately short. The named tasks and `all` run the stated
full recipes. `--plots` with `all` uses the recomputed data, not the reference
records. An explicit `--output` must name a new directory; existing output trees
and reference data are protected. Each run contains `execution_manifest.json`,
`numerical_checks.json`, `numerical_comparison.json`, sources' hashes, compiled
programs, logs and generated data. The per-program timeout can be changed using
`--timeout`.

## Evidence and interpretation

See the [numerical conventions and comparisons](numerical-notes.md).
Symbolic identities, floating-point residual checks, finite-time exponents and
numerical continuation are distinct kinds of evidence. The latter are not
interval-certified. Chaotic trajectories and finite-time scan values should not
be expected to agree pointwise solely because the equations and nominal step
sizes agree. Compare the stored and recomputed values and convergence settings.

The tangent-space spin scanner uses the explicit uniform-period recipe given
in the Part I guide. Its finite-time results differ from the paper reference
table as described in the numerical notes. Refinement recipes specify their
numerical seed, grid and integration step in `configs/refinement_recipes.json`.

The optional MATLAB examples are translations for interactive use. The tested
workflow is Python/C++; see the [environment information](tested_environment.json)
for the operating system and versions.

## Independent implementation checks

```bash
python quaternions-to-pentarnions/tests/check_native_models.py --help
python quaternions-to-pentarnions/tests/check_spin_scan_adaptive.py --help
```

The first compares compiled model fields with an independent Python model. The
second accepts the short spin CSV generated by `run_numerics.py --task smoke`
and integrates the same initial-value/tangent problem independently with DOP853.
Both write separate machine-readable reports. These tests complement, rather than
replace, the full workflows and reference comparisons.
